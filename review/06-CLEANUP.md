## Commit by commit

### 1 — `63374ef` Stop tracking release binaries

- **Removed from tracking:** `public/downloads/Juno.dmg` (21.9 MB), `dist/SHA256SUMS-b722da0.txt`, `dist/SHA256SUMS-c37010f.txt`.
- **Why the .dmg:** it is build output in a tree that `deploy.yml` rsyncs to the VM on every push, and the download menu already resolves release assets from GitHub Releases at runtime (`src/app/api/downloads/route.ts` → `src/lib/app-downloads.ts`). Nothing reads the committed copy.
- **Why those two checksum files:** `.gitignore:52-54` already stated the intent — delivery docs and checksums tracked, binaries not — but two per-commit snapshots for superseded builds had accumulated. `dist/SHA256SUMS.txt` and the three delivery docs stay.
- **`.gitignore`:** added `dist/SHA256SUMS-*.txt` and `/public/downloads/*.{dmg,zip,pkg}`.

### 2 — `6cf1be8` Untrack the generated i18n catalog; gate PRs in CI

- **Removed from tracking:** `src/lib/i18n-catalog.generated.ts` (195 KB, 9,468 lines).
- **Verified before deleting:** removed the file, ran `npm run i18n:extract`, `diff`'d against the tracked copy → **byte-identical**. Then `npx tsc --noEmit` → exit 0. It is generated by `predev` and `prebuild` (`package.json:6,8`), so tracking it only meant every `npm run dev` left a 195 KB diff in the working tree.
- **Deliberately NOT untracked:** `src/lib/models.generated.ts` and `src/lib/benchmarks.generated.ts`. Those look generated but are **curated registry state** committed by `sync-models.yml`, and are not reproducible without provider API keys. Untracking them would silently empty the model catalog on a fresh clone. The distinction is now written into `.gitignore` and `CONTRIBUTING.md`.
- **CI, made necessary by the above:** the `test` job runs `npm run i18n:extract` before `tsc --noEmit`.
- **CI, an improvement in its own right:** `deploy.yml` now triggers on `pull_request`, and `build-and-deploy` is guarded with `if: github.event_name != 'pull_request'`. Before this, the web surface had **no PR gate at all** — typecheck, tests and lint ran only on push to `main`, i.e. after the merge, on the way to production. (`native.yml` already gated PRs correctly.)

## File-history problems that need your decision

I did not rewrite history, as instructed. Three things are now removed from the tip but still in every clone.

### 1. `public/downloads/Juno.dmg` — 21.9 MB, permanently in the pack

Deleting it from the tip does not shrink a clone. Every `git clone` still transfers it. Options:

- **Leave it.** 22 MB is annoying, not fatal. Zero risk. This is what I would do unless clone time is actually hurting.
- **`git filter-repo --path public/downloads/Juno.dmg --invert-paths`**, then force-push. Rewrites every commit SHA that touched it. Everything downstream — the deploy VM's checkout, any open branch, any clone, the 43 uncommitted `native/` changes if they are ever rebased — has to be reset. For a solo repo this is survivable; it is still a bad afternoon.

**My recommendation: leave it**, and never let a binary in again — `.gitignore` now covers the pattern and the pre-commit hook covers the secret case.

### 2. `src/lib/i18n-catalog.generated.ts` — ~195 KB × every revision

Regenerated nightly-ish across the project's life, so the pack holds many near-identical copies. Same trade-off, smaller stake. Same recommendation: leave it.

### 3. No secret was ever committed — verified

`git ls-files` matching `\.env|\.pem|\.key|secret|credential` returns only `.env.example`, source files whose *names* contain those words, and `native/.../SecretRedactor.swift`. **There is no credential in this repository's history that I could find**, so none of the above is urgent. That is the good news, and it is the reason a history rewrite is optional rather than mandatory.
