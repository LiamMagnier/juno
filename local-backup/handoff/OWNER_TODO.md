# Alevr owner setup

## G08 - First-party connectors

Implementation branch: `codex/first-party-connectors`. All six apps are hidden until their dedicated app credentials are configured. No production configuration or secrets were changed by this work.

- Google: create a Web application OAuth client; enable Gmail, Calendar and Drive APIs. Add redirects `https://<your-app-host>/api/connectors/gmail/callback`, `/api/connectors/google-calendar/callback` and `/api/connectors/google-drive/callback`. Configure `CONNECTOR_GOOGLE_CLIENT_ID` and `CONNECTOR_GOOGLE_CLIENT_SECRET` through your normal private deployment process. They are separate from Google sign-in credentials. Review the exact per-app scopes in `src/lib/first-party-connectors/providers.ts`; complete restricted Gmail scope verification/CASA before public use. Offline consent is requested and tokens are encrypted and refreshed.
- Microsoft: register an Entra confidential Web app, choose supported account types, and add redirects `/api/connectors/outlook/callback` and `/api/connectors/microsoft-365/callback` on the app host. Configure `CONNECTOR_MICROSOFT_CLIENT_ID` and `CONNECTOR_MICROSOFT_CLIENT_SECRET`. Grant delegated User.Read, offline_access, Mail.ReadWrite, Mail.Send and Calendars.ReadWrite for Outlook; Files.Read.All and Sites.Read.All for Microsoft 365. Obtain any required tenant administrator consent.
- Slack: create a confidential OAuth app; add `/api/connectors/slack/callback` on the app host; configure `CONNECTOR_SLACK_CLIENT_ID` and `CONNECTOR_SLACK_CLIENT_SECRET`. Enable token rotation. User OAuth scopes are search:read, channels:read/history, groups:read/history, im:read/history, mpim:read/history and chat:write. Slack public-client PKCE is not needed for this confidential server flow. Install it in a test workspace and verify search/history/send permissions with a real user.
- After the shared trigger integration requested in LANES.md lands, exercise connector_event triggers using Gmail/Drive/Calendar/Outlook/Microsoft 365 and a Slack channel stream. Until that integration lands, connector_event remains intentionally refused. The new sync endpoint and durable outbox are implemented; vendor push subscriptions and their verification/renewal are still separate work. This implementation uses incremental API reads, not live push delivery.
- Perform live consent, refresh, reconnect/revoke, draft and approved-send acceptance checks against test accounts. Automated checks use fake providers and a disposable local database; they do not establish vendor acceptance.
