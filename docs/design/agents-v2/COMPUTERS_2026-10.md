# Agent computers, October 2026: the build plan

Plan only. Nothing in this document is built yet. Written 2026-10-27 against `7c91a0c2e`
(main, live in production). It is the contract for six build stages, S1 to S6. The stages
do not edit this file; S6 appends a "Result" section at the end.

The owner's ask: Orbit agents that really work and can start their own Linux computer.
The hard rules that bind every stage are in the brief; the ones that shape this plan:

- Production stays off by default. An empty `COMPUTER_PROVIDER` (or
  `AGENT_COMPUTER_PROVIDER`) means no computers, exactly as today.
- Gates are added, never removed or weakened. The per-action floors stay:
  `computer_shell`, `computer_type` and a text-producing `computer_key` are `sensitive`
  and ask every time. Unattended runs never get a standing grant to run commands.
- No deploys, merges, billable actions, live credential changes or commercial changes.
  New owner-tunable numbers go in env with conservative defaults and are listed in
  `docs/OPEN_DECISIONS.md` as "owner to confirm".
- Anything not executed is reported as `not_run` or `unverified`.
- There are no AI provider keys on the build machine. Every model-driven test or demo
  uses the scripted Work model (S1) and says so.

## 0. Order of work

```
Phase 1:  S1 (gating, quotas, policy, self-start, scripted model, honesty)   ∥   S2 (container, image, network, takeover primitives, retention, docs)
Phase 2:  S3 (remote computer host, RemoteComputerProvider, tunnels, relay)
Phase 3:  S4 (real-container end-to-end tests in CI)   ∥   S5 (streamed shell, terminal pane, binary files, inbox, publish)
Phase 4:  S6 (local end-to-end demo of the real product, screenshots, UX fixes)
```

A stage starts only when every stage of the previous phase has finished and reported.
Two stages in the same phase never own the same file (section 3).

  bandwidth cap).

  bounded today), takeover window with epoch fence, VNC rotation at hand back.
- The sweep (`sweep.ts`, called from the Work runner's tick at `work-runner.ts:2860`,
  every 60 s): reboot reconciliation, expired leases, idle stream stop, rest after 3 min,
  sleep after 30 min, disk over quota, orphan reaping after 10 min.
- Live view: single-use relay tokens (`live-view.ts` `mintViewToken`), the relay dials only
  `RELAY_COMPUTER_CIDR` on port 5900 (`relay/src/computer-view.ts:101-114`).
- CI job `computer-boundary` (`.github/workflows/deploy.yml:696`) attacks a real container
  behind `firewall.sh` and `egress-proxy.py`; it is required before deploy.

### Deviations from the lead's decisions, and why

- **D1. The store-level takeover wiring moves from S2 to S1.** Freezing at take over,
  thawing and rotating at hand back and at lapse, the `takeover_lapsed` audit and the
  wake/sleep/hand-back audit all live in `src/lib/computer/store.ts`, which S1 must own
  for gating and metering. A file has one owner per phase. S2 builds the provider
  primitives (`freezeAgent`, `thawAgent`, `browserSandbox`, `isOutdated`) and proves them
  on a real container; S1 wires them with the fake provider; S4 proves the wiring end to
  end on a real container. The security content of decision 6 is unchanged.
- **D2. Audit goes to a new table, `AgentComputerAudit`,** not to `AgentEvent` (the
  person's visible agent log, which rest/wake every few minutes would flood) and not to
  `WorkAuditEvent` (its writer, `src/lib/work/audit.ts`, belongs to another job). The
  existing visible events (`takeover_started`, `takeover_ended`, `computer_enabled` …)
  stay as they are.
- **D3. Freeze kills input injectors instead of stopping them.** At take over, uid-1000
  `xdotool` and `scrot` get SIGKILL; every other uid-1000 process gets SIGSTOP, and SIGCONT
  at hand back or lapse, as decided. Resuming a stopped `xdotool type` would finish typing
  into whatever field the person left focused. The tool call it belonged to is already
  discarded by the epoch fence.
- **D4. The call that raises "Start <name>'s computer" only starts the computer.** It
  returns "Started your computer. Nothing else was done…" and the model repeats the
  action, which then goes through its own approval as usual. One approval authorises one
  thing, the digest stays over that one action, and the shell's own card still appears.
  Under `allowed` the first call starts the computer and performs the action.
- **D5. Tunnel tickets are minted by the host,** single use, 60 s, bound to one container
  and one port. The relay never holds the host's bearer token: the app asks the host for a
  ticket and hands it to the relay sealed inside the relay token (AES-256-GCM, key derived
  from `AUTH_SECRET`), so neither the browser nor a log sees it. The host cannot verify the
  app's relay token, because it holds no app secrets; the ticket is how it authenticates
  the tunnel.
- **D6. The host's broker is reached through a root-owned Unix socket** (the
  `deploy/exec-host` pattern), not sudo, so the host service can run with
  `NoNewPrivileges=yes`. The argv policy is the same `validate()` from
  `deploy/agent-computers/docker-broker.py`, imported, not copied.
- **D7. Per-plan computer entitlement and caps are a new map `PLAN_AGENT_COMPUTER` in
  `src/lib/plans.ts`,** not new `PlanConfig` fields. `PlanConfig` is the commercial record
  the billing surfaces read (`src/lib/billing/plan-capabilities.ts`, the plans page,
  Stripe price keys); leaving it untouched means no existing entitlement changes and no
  plan surface starts advertising computers while they are off. The caps are numbers with
  env overrides, which `PlanConfig` does not carry. A test holds the map's entitlement
  equal to `PLANS[plan].agents`.
- **D8. Streamed shell output is stored in a new table, `ComputerShellOutput`, and read by
  a new computer route,** not written as a new `WorkEvent` kind. `WORK_EVENT_KINDS` is a
  contract pinned by the native apps and owned by another job. The final, capped output
  still lands in the run as today.
- **D9. The scripted model needs one dev-only line in `src/lib/work/dispatch.ts`,** a file
  the Orbit runtime job owns, because dispatch refuses when no provider key is
  configured. The hook is inert unless `NODE_ENV` is not production, the opt-in variable is
  set, a script file is set, and the account is listed.
- **D10. DNS: the resolver exception is removed AND the provider's `--dns` is pinned to a
  never-routed sentinel with port 53 REJECTed,** so lookups fail at once instead of timing
  out. Removing `--dns` alone may let Docker's embedded resolver fall back to the host's
  own resolvers, and recent Docker releases forward to a loopback host resolver from the
  host's namespace, outside the bridge firewall (to be confirmed, not assumed); S2 proves
  the result on Docker 29.9.2 here.
- **D11. Two additions to decision 6:** x11vnc only accepts connections from the bridge
  gateway (`-allow 172.30.0.1`), so the agent cannot reach VNC on its own loopback; and
  agent execs get `-e HOME=/home/agent` (fact 17), which pip, venv and npm need.
- **D12. One addition to decision 5:** `AGENT_COMPUTER_REQUIRE_BROWSER_SANDBOX` (default 0)
  lets the owner refuse to wake a computer whose Chromium sandbox is off. Default 0 keeps
  today's behaviour (sandbox off) available and reported.

### 3.2 Rules for everyone

- Use the Edit tool on existing files; never Write over one. `scripts/work-runner.ts`
  (4,350 lines) is shared with the Orbit runtime job, which owns its park/ask/approval,
  provider-fault and shutdown parts: small localized edits only, no reformatting, no
  moved code.
- Never run `git add/commit/stash/checkout/reset/restore/clean`. Never delete a file you
  did not create.
- Optional provider methods (S1/S2 seam). S1 adds to `ComputerProvider`, as optional:
  ```ts
  /** SIGKILL uid-1000 xdotool and scrot, then SIGSTOP every other uid-1000 process. Idempotent. */
  freezeAgent?(handle: ComputerHandle): Promise<void>;
  /** SIGCONT every uid-1000 process. Idempotent. */
  thawAgent?(handle: ComputerHandle): Promise<void>;
  /** Whether Chromium in this computer runs with its own sandbox; "unknown" when it is not running. */
  browserSandbox?(handle: ComputerHandle): Promise<"on" | "off" | "unknown">;
  /** Whether the container was created from an image older than the current security label. */
  isOutdated?(handle: ComputerHandle): Promise<boolean>;
  ```
  S2 implements them in `docker.ts` with exactly these signatures. S3 makes all four
  required once the remote provider implements them, so no provider can silently skip
  them. Until then S1 calls them with `?.` and records an audit row
  `freeze_unavailable` when a provider lacks `freezeAgent`.
- Evidence goes under
  `/tmp/claude-0/-home-user-juno/fa198b77-5ed6-5d1e-9041-b11ebba8d703/scratchpad/computers/<stage>/`.
  Every screenshot taken is looked at with the Read tool before it is cited.
- Docker: at most 2 computer containers awake at once per stage. Remove every container,
  network and volume the stage created. The host fixture (network `juno-computers`,
  firewall rules, egress proxy) belongs to S2 in phase 1, S3 in phase 2, S4 in phase 3,

  // …existing fields…

/// One metered awake interval. Idempotent per (agentId, startedAt), like the spend key.
/// No foreign key to Agent: usage must survive an agent's deletion within the week.

  id        String   @id @default(cuid())
  userId    String
  agentId   String
  startedAt DateTime
  seconds   Int
  /// Monday 00:00 UTC of the week `startedAt` falls in.
  weekStart DateTime
  runId     String?
  createdAt DateTime @default(now())
  user      User     @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@unique([agentId, startedAt])
  @@index([userId, weekStart])
}

/// Operator audit for computers. Identifiers and verdicts only (writer: src/lib/computer/audit.ts).
model AgentComputerAudit {

### S1.2 Weekly allowance and metering

- `billComputerSeconds` records an `AgentComputerUsageInterval` (`createMany` with
  `skipDuplicates`, key `(agentId, startedAt)`) **before** its price check, so time is
  metered at price 0. The spend write keeps its own idempotency key, unchanged.
- `disableComputer` meters the open interval before it destroys (today it drops it).
- `computerAllowanceRefusal(userId, now)` = this week's intervals plus the accrued
  seconds of every awake computer of the account (`now - lastResumedAt`) against
  `weeklyMinutes`. Intervals count in the week they started.
- `computerUsageBudgetRefusal` (the name the sweep already calls, so `sweep.ts` needs no
  change) becomes: access refusal, then allowance refusal, then the existing spend check.
  It no longer returns null early when the price is 0. Callers: `ensureAwake`,
  `renewComputerLease` (a refusal releases the lease, sleeps the computer, writes
  `lastError`, audits `slept` with the reason), and the sweep.
- Enabled cap: a new persistence method `claimEnableSlot(userId, agentId, maxEnabled)` that
  counts the account's `AgentComputer` rows other than this agent's and inserts the row in
  one transaction under `pg_advisory_xact_lock(hashtext('juno.agent-computer.enabled:' || userId))`;
  the in-memory persistence gets the same method.

### S3.1 The host service (`deploy/computer-host/juno-computer-host.py`)

Python standard library plus `python3-websockets` (apt). Two listeners on 127.0.0.1:
the API (`apiPort`, threaded `http.server`) and the tunnels (`tunnelPort`, asyncio
`websockets`), in one process sharing the ticket store. nginx terminates TLS on 443 and
routes `/v1/tunnel` to the tunnel port with Upgrade headers, everything else to the API.

Every request: `Authorization: Bearer <token>`, compared with `hmac.compare_digest`; the
service refuses to start with a token under 43 characters. Container names must match
`juno-agent-[A-Za-z0-9_-]{1,120}`. Every Docker call goes through the broker socket (D6):
`/run/juno-computer-host/broker.sock`, root:juno-computer-host 0660, socket-activated,
one JSON request `{argv, stdin_b64?}` per connection, framed stdout/stderr/exit back,
`validate()` and the `app=juno` namespace inspect of `main()` imported from
`deploy/agent-computers/docker-broker.py` (refactor `main()` so both entry points share
one function), with the host's policy file and the same fixed environment. Logs: operation, container name, duration, status. Never a command, file content,
token, password or ticket.

API v1 (JSON unless noted):

| Call | Provider method |
|---|---|
| `GET /v1/health` | (ops) image, label, running count, version |
| `GET /v1/available` | `available()`: the image exists and carries the current label |
| `GET /v1/preflight` | `preflight()`: host `MemAvailable`, free disk on the Docker root, running count against `maxRunning` |
| `POST /v1/computers` `{agentId, userRef}` → `{name, volume}` | `create()`; `userRef` is `u_` + the first 32 hex of sha256(userId), never the id |
| `POST /v1/computers/{name}/start` · `/stop` · `/pause` · `/unpause` | lifecycle; start and unpause also refuse past `maxRunning` |
| `DELETE /v1/computers/{name}?volumes=1` | `destroy()` |
| `GET /v1/computers/{name}/state` | `state()` |
| `PUT /v1/computers/{name}/cdp-token` (raw body) | `provisionCdpToken()`; passed through stdin, never stored or logged |
| `GET /v1/computers/{name}/screenshot` → `image/png` | `screenshot()`; the app converts to JPEG as today |
| `POST /v1/computers/{name}/input` `{kind: click\|type\|key\|scroll\|drag, …}` | the five input methods, same validation as `docker.ts` |

### S5.1 Streaming

- `ComputerProvider.exec(handle, command, opts?: { timeoutSeconds?; cwd?; onOutput?:
  (chunk: { stream: "stdout" | "stderr"; text: string }) => void })`. Docker: a new
  `spawnDockerStreaming` in `docker-cli.ts`; remote: `POST …/exec` with
  `Accept: application/x-ndjson` returns `{stream, data_b64}` lines and a final
  `{exit, timedOut, durationMs}`. The returned `ExecResult` is unchanged.
- Runner: the shell dep passes `onOutput` to `shell-output.ts`
  `appendShellOutput({userId, agentId, runId, callId, stream, text})`, which batches every
  250 ms, encrypts, numbers `seq`, writes a `command` row first and an `exit` row last, and
  stops storing past `AGENT_COMPUTER_SHELL_LOG_KB_PER_CALL` with a final row "[output
  continues; the rest is in the result]". The model's result keeps today's 20,000-character
  cap per stream.
- `GET /api/agents/[id]/computer/shell?runId=&after=<seq cursor>` (owner-scoped, gated like
  view) returns decrypted rows after the cursor; the pane polls every 1 s while a shell call
  is running and stops when the run ends.
- `computer-terminal.tsx`: monospace, read-only, `role="log"`, `aria-live="off"`, no input
  element, no key handler that sends anything; ANSI escapes stripped; "$ <command>" headers;
  exit code lines; follows the bottom unless the person scrolled up. Placed in the computer
  overlay beside the live view (a "Terminal" tab on narrow screens).

### S5.2 Binary-safe files

- Agent-core deps: `readFile(path, maxBytes): Promise<Uint8Array>`,
  `writeFile(path, bytes: Uint8Array): Promise<void>`. `computer_files` gains
  `encoding: "utf8" | "base64"` (default utf8). A utf8 read of bytes that are not valid
  UTF-8 (or contain NUL) answers "{path} is a binary file ({size}, sha256 {first 12 hex}).
  Read it with encoding base64, or publish it." Base64 reads keep the 200 KB cap on the raw
  bytes. Writes decode base64 when asked; path rules unchanged.
- `files.ts` `uploadToComputerInbox`: `POST /api/agents/[id]/computer/files` with the raw body
  and `X-File-Name`; computer must be awake or resting; gated; 30 per hour; size ≤
  `AGENT_COMPUTER_UPLOAD_MAX_MB` (checked from `Content-Length` and while reading); name:
  basename only, no control characters, no leading dot, ≤ 200 characters, a collision gets
  " (2)", " (3)"…; refused when the computer is over its disk quota; written as uid 1000 to
  `/home/agent/work/inbox/<name>` through `writeFile` (realpath recheck, work-area rule);
  audited `file_uploaded`. The overlay's file browser gets "Add a file".

### S5.3 Publish as deliverable

`computer_files` action `publish` `{path, title?}`: risk and action of `create_deliverable`;
reads the regular file (≤ 25 MB), picks the MIME type from an extension allowlist (pdf, png,
jpg, gif, webp, csv, txt, md, json, html, docx, xlsx, pptx, zip; anything else
`application/octet-stream`), stores it through `storeDeliverable` with `origin: "computer"`,
always as an attachment download (never rendered inline), and records `artifact_created`
as other deliverables do. Audited `file_published`.

## 7. What stays open after this plan

Recorded so nobody reads this plan as closing them:

- The CDP gate is a pass-through (no method allowlist). Acceptable while only the app holds
  the token and no tool exposes raw CDP; needed before any tool does.
- A page flooding protocol events, or a message over 64 MB, stops the gate and the
  computer.
- `AllowFileSelectionDialogs` is undecided: the file dialog as uid 1001 can upload profile
  files.
- Image rebuilds (Chromium updates) are by hand; S1.6 rebuilds outdated containers on wake,
  but nothing schedules the image build.
- `Xvfb -ac` stays: uid 1000 must drive the display by design (the review's correction).
- Pixel clicks on submit controls are not escalated unless the page takes payment.
- The disk quota is measured, not enforced by the filesystem.
- The egress proxy allows any public host on 80 and 443 (owner decision 5).
- Answering a parked run does not requeue it (the Orbit runtime job's fix). Until it
  lands, an unattended run parked on "Start {name}'s computer" needs Resume after approval,
  like any parked approval today.
- The native apps show nothing new: they keep hiding the computer when `computer` is null,
  and the policy control and access line are web only. Native parity is a follow-up that
  needs a Mac to compile.

## 8. Owner decisions

Defaults are what ships; nothing changes until the owner says so.

1. **The computer host.** A dedicated Linux AMD64 VM (recommended; it can later also carry
   `juno-exec`) or a hosted sandbox vendor (a new subprocessor in `docs/SUBPROCESSORS.md`, a
   DPA, per-second billing). Region: same as the web VM (Azure Sweden Central) for latency
   and EU residency. Size, by arithmetic from the caps, not a measurement: each awake
   computer is capped at 2 GB RAM (no swap) and 2 CPUs; reserve 2 GB for the OS, Docker,
   proxy and service, and keep the 1 GB free-memory floor; so 6 awake computers need about
   16 GB RAM, plus disk for the image (about 1.8 GB), the 10 GB free-disk floor and up to
   10 GB per enabled computer (soft quota). Who holds SSH (`--ssh-from`), the domain and the
   certificate.
2. **Which plans and how much.** Default: every plan where `agents` is true (Pro and up).
   Computers per account and awake minutes per week per plan (4.2). Awake caps per account
   (2) and per host (6).
3. **The price.** `COMPUTER_COST_MICRO_USD_PER_SECOND`, default 0. At 0 the weekly allowance
   still bounds use; above 0 computer time also draws on the usage windows.
4. **Rollout.** Who is on `AGENT_COMPUTER_ALLOWLIST` first (owner and staff), and when, if
   ever, to switch to `plans`.
5. **Egress.** Any public host on 80 and 443 (today) or an allowlist; the per-computer
   budget (1024 MB per hour); how long the egress log is kept (journald's default unless
   set).
6. **Unattended command grants. Default: no.** Shell, typing and text keys ask every time;
   an unattended run notifies and parks. Any narrower grant ("may run commands in its own
   computer") would need an egress allowlist for that computer, an audit of commands and
   connections, plan gating, and would never cover typing into pages or payments.
7. **Retention.** `COMPUTER_RETENTION_DAYS`, default 0 (off). A number deletes files and
   sign-ins and needs a user notice first.
8. **Chromium's sandbox.** Whether to require it (`AGENT_COMPUTER_REQUIRE_BROWSER_SANDBOX=1`).
   It depends on the host's kernel and AppArmor; S2 records what this machine allows, not
   what a production host allows.
9. **Uploads and logs.** The inbox cap (25 MB) and the streamed-output cap per call (512 KB).
10. **Downgraded accounts.** Today's plan: their computers stay asleep and intact; they can
    delete them but not wake them. Whether to offer an export first.
11. **The default policy for new agents.** `ask` in this plan.
12. **Image rebuild cadence** for Chromium security updates.
13. **The review items in section 7** that need a decision (`AllowFileSelectionDialogs`).
