# Other references worth stealing from, only where they beat Claude or Figma

Lens: **other references for a merged "things the AI makes + design" surface in Juno.**
Research date: 2026-09-23. Baseline: `docs/design/artifacts-design/research/claude-primary-evidence.md`, which is authoritative for Claude's typed artifacts (Design, Design System, Docs, Slides, capabilities, comments sent to Claude, versions, the 16 Sept merge). The local Figma plugin skills are the baseline for Figma (motion: manual keyframe tracks, animation styles, cubic and spring easing, timelines, `export_video`; plus shaders, Slides, FigJam, generative plugins, Code Connect, Weave).

**Confidence tags:** **[P]** primary (vendor page or doc, or a vendor tool surface seen locally). **[P·snip]** vendor page known only from a search-result snippet, because the page returned 403 to fetch. **[S]** secondary (press, reviews, aggregators). **[I]** inferred by me.

**Method note:** openai.com, help.openai.com, canva.com/newsroom, gamma.app and businesswire returned HTTP 403 to fetch. For those I used search snippets of the vendor page, marked [P·snip], or press coverage [S]. The session's shared web-search budget ran out partway through. ## 0. TL;DR: the 14 ideas that clearly beat Claude and Figma for Juno's merged surface

Ranked by how much each would improve a merged Artifacts + Design surface. Each item says where Claude or Figma falls short, which is the reason it is on this list.

1. **Comments are the AI's inbox, and the whole thread goes with them (Lovable).** Comment pins sit on elements of the live preview. `@Lovable` or "Send to chat" sends *the full thread, the page and the element* to the agent as structured context. Resolved threads hide. **A pin whose anchor disappears after a layout change shows a "lost reference" indicator.** Writing a comment is free; only the send costs credits. The toolbar has single-key modes: `S` select, `T` text, `D` draw, `C` comment. Claude has comments sent to Claude, but nothing in the evidence covers orphaned anchors, single-key modes or credit-free comments. [P] [docs.lovable.dev/features/project-comments](https://docs.lovable.dev/features/project-comments) (launched 2026-04-02 [P] per the [Lovable changelog](https://docs.lovable.dev/changelog)); [docs.lovable.dev/features/design](https://docs.lovable.dev/features/design) (toolbar 2026-06-10 [P] per the Lovable changelog; createwith's 2026-06-15 is its article date)
2. **Point, draw, or speak at a live running artifact, and queue the next edit while the agent is still busy (Cursor Design Mode).** You can click an element, Shift-drag an area, or draw over a **frozen frame**, so annotating an animated page captures the exact state you meant. You can also narrate by voice; the mic stays available while agents run, so you can queue the next change by voice. The agent receives xpath, attributes, computed styles, React fiber props *and* a screenshot. You can send edit #2 before edit #1 finishes, and it runs in parallel subagents. Design Mode first shipped in Cursor 3.0 (2026-04-02). Cursor 3.7 (changelog 2026-06-04) added multi-select, voice, and Design Mode inside Cursor's **canvases** (agent-made interactive artifacts). Lovable's toolbar (2026-06-10) also lets you queue the next change while the agent works, so queueing is not unique to Cursor. Claude Design's annotations and view-state apply to the Design canvas. The evidence doesn't extend them to HTML or React artifacts, and it shows no edit queue. [P] [cursor.com/blog/design-mode](https://cursor.com/blog/design-mode) (2026-06-05); [cursor.com/docs/agent/design-mode](https://cursor.com/docs/agent/design-mode); [cursor.com/changelog](https://cursor.com/changelog/page/4)
3. **Every generation lands as its own iteration on the canvas, and directions are branches you manage (Google Stitch).** An infinite canvas keeps variants side by side instead of overwriting them. The "Agent Manager" tracks several directions in parallel. Since I/O 2026 the agent **streams its work straight onto the canvas and can be steered before it finishes**. Claude Design places artboards, but its evidence has no notion of first-class branches or directions, and no mid-generation steering. [P] [blog.google, Stitch real-time design](https://blog.google/innovation-and-ai/models-and-research/google-labs/stitch-updates/) (2026-05-19); March redesign with Agent Manager [P] [blog.google](https://blog.google/innovation-and-ai/models-and-research/google-labs/stitch-ai-ui-design/) (2026-03-18). "Stitch 2.0" is a press label, not Google's name [S] [winbuzzer](https://winbuzzer.com/2026/03/20/google-redesigns-stitch-ai-voice-canvas-developer-integrations-xcxwbn/) (2026-03-20)
4. **One library for everything, uploaded or made, with folders, per-person Viewer/Editor sharing, "Shared with me", cloud-drive sources, and "Add from Library" in the composer (ChatGPT Library).** Claude's gallery lists artifacts, but the evidence shows no folders and no per-file role sharing that covers uploads as well. Juno's audit counts seven "show me what Juno made" paths (§4.5), and this is the pattern that collapses them. [P·snip] [help.openai.com Library](https://help.openai.com/en/articles/20001052-file-storage-and-library-in-chatgpt); Library sharing 2026-09-09 and cloud sources 2026-09-10 [P, via the releases.sh mirror of OpenAI's release notes] [releases.sh](https://releases.sh/openai/chatgpt-release-notes.md)
5. **One source, many typed outputs, from a "Create" button (Gemini Canvas; NotebookLM Studio).** From a doc, Gemini's Create menu makes a web page, infographic, quiz, Audio Overview or slides. NotebookLM's Studio column shows creation tiles plus a list of outputs. It holds **several outputs of the same type**, lets you use one while another generates, and per-slide feedback **regenerates the deck as a new sibling** rather than overwriting it. Claude decides the type for you and offers no visible "turn this into…" affordance. [P] [support.google.com Gemini Canvas](https://support.google.com/gemini/answer/16047321?hl=en&co=GENIE.Platform%3DDesktop); [blog.google NotebookLM Studio](https://blog.google/innovation-and-ai/models-and-research/google-labs/notebooklm-video-overviews-studio-upgrades/) (2025-07-29); [Workspace Updates](https://workspaceupdates.googleblog.com/2026/03/new-ways-to-customize-and-interact-with-your-content-in-NotebookLM.html) (2026-03-20)
6. **AI proposes edits as a reviewable queue, top to bottom (Notion Suggested Edits).** The agent suggests rather than applies, and you approve or reject each suggestion in order. Claude revises in place, with versions and conflict refusal. Juno already has preview-then-accept for Ask Juno on designs, and this generalises it to documents and code artifacts. [P] [notion.com/releases/2026-08-28](https://www.notion.com/releases/2026-08-28)
7. **AI edits go to a branch; merge when happy (Framer Agents; v0).** Framer offers to "Iterate safely by moving AI agent edits to a branch". Framer 3.0 (2026-06-16) shipped Agents together with Branching: work on a copy, then merge or throw it away. In the new v0, a Git panel lets you "create a new branch for each chat, open PRs against main, and deploy on merge". Auto-commits are (unverified). Claude has linear versions with labels, and Figma branching is manual and for Enterprise [I]. [P] [framer.com/agents](https://www.framer.com/agents/); [framer.com/blog/framer-3](https://www.framer.com/blog/framer-3/) (2026-06-16); [vercel.com/blog/introducing-the-new-v0](https://vercel.com/blog/introducing-the-new-v0) (2026-02-03)
8. **Import any other AI's HTML as an editable design, and embed code artifacts inside decks and whiteboards (Canva Code 2.0).** You can click generated elements to change text, drag in assets from the 120M-item library, and restyle from the toolbar. HTML "from any source, including ChatGPT, Claude, Lovable, or Bolt" becomes a *fully editable design*. Code projects can be created *inside* other designs. Claude's Slides type has `<x-embed>`, but Claude cannot turn arbitrary HTML into editable design layers. [S] [VentureBeat](https://venturebeat.com/technology/canva-launches-code-2-0-offering-ai-website-building-to-every-user-including-free-accounts) (2026-07-14)
9. **"Save a version" is kept separate from "Deploy a version" for hosted app artifacts, with identity, data, analytics and custom domains (ChatGPT Sites).** Sites have D1 and R2 storage, Sign in with ChatGPT through request headers, traffic analytics and custom domains. Audiences run from owner-only through workspace to public. Claude's artifacts have `db`, `user` and private links, but the evidence shows no staging-versus-live split, no analytics and no custom domain. [P] [learn.chatgpt.com/docs/sites](https://learn.chatgpt.com/docs/sites); launched 2026-07-09 [S] [playcode](https://playcode.io/blog/chatgpt-sites-explained)
10. **Positional comments on generated images, in full-screen image editing (ChatGPT Images 2.5).** OpenAI's release note (2026-09-08) says: on mobile, open a generated image full screen to edit it or add comments. Templates, sketch-to-image (mobile) and prompt sharing came in the same release. That each comment pairs a *position* with an instruction comes only from a secondary guide. This extends the comment-to-AI loop to raster media, which Claude's evidence doesn't cover. [P, via the releases.sh mirror] [releases.sh](https://releases.sh/openai/chatgpt-release-notes.md); [S] [testingcatalog](https://www.testingcatalog.com/openai-launches-chatgpt-images-2-5-with-faster-editing/) (2026-09-09, doesn't mention full screen); [atlascloud](https://www.atlascloud.ai/blog/tips/gpt-image-2.5-image-comments) (2026-09-16, positional)
11. **DESIGN.md: an open, portable design-rules file that agents read (Stitch).** It was open-sourced on 2026-04-21 and can be imported or exported between tools. Claude's Design System type is richer, but it is proprietary. Juno should *read and write* DESIGN.md alongside its own system. [P] [blog.google DESIGN.md](https://blog.google/innovation-and-ai/models-and-research/google-labs/stitch-design-md/)
12. **Display modes as a contract: inline card, then full screen with a persistent overlaid composer, then picture-in-picture (ChatGPT apps).** The inline card allows at most 2 actions and no nested scroll. Full screen keeps the system composer on screen so you can follow up in context. PiP stays pinned while you chat. ChatGPT *removed the side-panel Canvas* in mid-2026, in favour of inline writing and code blocks that open full screen. That is a strong counter-signal to Juno's side-panel-first Canvas. [P] [developers.openai.com Apps SDK UI guidelines](https://developers.openai.com/apps-sdk/concepts/ui-guidelines); Canvas sunset [S] [ai-toolbox](https://www.ai-toolbox.co/chatgpt-management-and-productivity/how-to-use-chatgpt-canvas-guide-2026)
13. **Pull live UI onto the canvas and push it back as code (Subframe; Paper).** Subframe's macOS app combines an infinite canvas, a built-in browser and an agent (your own Claude Code or Codex). You can *capture live browser elements onto the canvas*, and components map 1:1 to code, down to the pull request. Paper's canvas *is* HTML/CSS. Agents work across files in background tabs, and comments address "teammates and your agents". Figma's canvas is not code, and Claude Design's `.dc.html` is code but has no "capture from live app". [P] [subframe.com](https://www.subframe.com/); [paper.design/build-log](https://paper.design/build-log) (Aug 2026); [paper.design blog](https://paper.design/blog/a-real-space-to-design-in-the-age-of-agents) (2026-02-27)
14. **Layered, editable AI output plus brand applied *retroactively* (Canva AI 2.0).** Every generated element is its own layer, and brand standards can be re-applied to existing designs in one step. Figma's AI output is layered too, but "re-brand everything I already made" is not a one-step action in Claude or Figma. [S] [CMSWire](https://www.cmswire.com/digital-experience/canva-ai-20-adds-agentic-design-tools/) (2026-04-15/16)

What did **not** clear the bar for motion: Figma already has keyframe tracks, animation styles and spring easing (local skill `figma-use-motion`). Only two outside ideas beat it. **Rive's state-machine graph** is stateful and interactive, where Figma is timeline-based. **Framer Agents write production motion from a prompt** ("staggered … fades in", "parallax") on a live site. See §3.

## 2. Deep dives

### 2.1 ChatGPT (OpenAI): Canvas removed, Library, Work, Sites, Images 2.5, apps

**What changed and when**
- **Canvas was sunset.** The OpenAI release note, as quoted, reads "canvas will no longer be available in GPT-5.5 Instant or GPT-5.5 Thinking". [ai-toolbox](https://www.ai-toolbox.co/chatgpt-management-and-productivity/how-to-use-chatgpt-canvas-guide-2026) (published 2026-05-30, updated 2026-09-16) dates it **2026-05-28**. [theaicareerlab](https://theaicareerlab.com/blog/chatgpt-what-changed-june-2026) is an article published 2026-06-24 that reports the removal without a date of its own. *Fact-check: the earlier "date conflict" was a misreading of that article's publication date.* OpenAI's release-notes page returned 403, and the releases.sh mirror only holds recent entries, so the 05-28 date remains secondary. Paid users kept Canvas on legacy models for a while ("until those are sunset", per theaicareerlab). No later release note restored it (unverified). [S]
- **Its replacements live inline in the message.** **Writing blocks** are "editable areas for draft text". You can edit and copy the text, ask ChatGPT to revise a selection or the whole draft, open the block full screen, undo or redo recent AI edits, and save supported documents to the Library. **Code blocks** can "Preview" HTML, React, SVG, Mermaid and Vega/Vega-Lite, and "Run" Python in a sandboxed workspace with a console. Edits "save with the conversation after a short delay", and the model uses the latest version on follow-up. [P·snip] (unverified: the page returns 403 and was re-read only via snippet) [help.openai.com, writing and code blocks](https://help.openai.com/en/articles/20001246-working-with-writing-blocks-and-code-blocks-in-chatgpt)
- The 2026-06-08 expansion made writing blocks handle long-form work (essays, PRDs, reports). It added a **full-screen editor**, save to **Library**, a **table of contents** for long documents, download (PDF, DOCX), and undo/redo fixes. [S] [ai-toolbox](https://www.ai-toolbox.co/chatgpt-management-and-productivity/how-to-use-chatgpt-canvas-guide-2026)
- Earlier signal: OpenAI Devs described code blocks with "split-screen views" and a "full-screen view" (unverified: x.com can't be fetched). [P] [x.com/OpenAIDevs](https://x.com/OpenAIDevs/status/2024600394299822096) (date not captured)
- *Why it matters for Juno [I]:* OpenAI tried a side panel and gave it up. The object now lives **in the message**, grows to **full screen** for real work, and is **filed in the Library**. Claude went the other way, to one link per artifact. Juno's merge should support both: an inline live card, and a promote-to-full-screen or open-at-link path. It should not force a side panel.

**ChatGPT Work (2026-07-09)**
- An agent for long tasks that produces "documents, spreadsheets, presentations, reports, and Sites". Plan mode gathers context, asks questions and produces a step-by-step plan you approve. Check-ins and action approvals can be configured. [S] [Bloomberg](https://www.bloomberg.com/news/articles/2026-07-09/openai-unveils-chatgpt-work-agent-to-field-tasks-for-hours) (2026-07-09); [digitalapplied](https://www.digitalapplied.com/blog/chatgpt-work-openai-agent-launch-2026); [OpenAI edu newsletter](https://edunewsletter.openai.com/p/introducing-chatgpt-work-a-more-capable) [P] (2026-07-09): "follow its progress, answer questions, redirect the work, and review the results"
- **Mode model:** "Chat, Work and Codex now live as tabs in one application", with a merged activity view of conversations and tasks. On mobile, scheduled Work tasks are visible and cloud Work sessions stay reviewable, but local file access and Computer Use are desktop-only. [S] [aitoolsreview](https://aitoolsreview.co.uk/insights/chatgpt-work) (2026-07-09; the earlier 07-19 was wrong). *Contrast [I]:* Claude removed the mode choice altogether (16 Sept). ChatGPT kept explicit modes.
- **Presentations:** `@Presentations` in the desktop app. It produces "a short slide plan, builds the presentation, and checks the rendered slides before returning the deck". A deck can "follow a reference presentation or saved template, preserve approved figures and branding". The **Template Creator** skill turns an existing deck into a reusable template, keeping layouts, typography, colours and brand elements. Output goes to PowerPoint, or to Google Slides when Drive is connected. *Correction:* the doc does not describe built-in versions. It suggests **duplicating a deck before major revisions** so you can revert. [P] [learn.chatgpt.com slide decks](https://learn.chatgpt.com/use-cases/generate-slide-decks). In the desktop app you "open supported presentations from the sidebar and select the part you want to change", and you can **mark a slide** that needs a new layout. [P·snip] (unverified: 403) [help.openai.com Work documents](https://help.openai.com/en/articles/20001278-creating-and-editing-documents-spreadsheets-and-presentations-with-chatgpt-work)
- **Office add-ins:** ChatGPT in Word (2026-09-17), alongside Excel and PowerPoint. It revises the selection from a sidebar. [S] [releases.sh](https://releases.sh/openai/chatgpt-release-notes)
- Deep research inside Work and Codex writes its output as "an editable document with citations, presentation, spreadsheet, or Site" (2026-09-10). [S] same

**Library (the unified gallery)**
- Library is where you find and reuse files you uploaded to ChatGPT or created in it. You can browse, search, download and delete saved files, and attach them to another conversation from the composer menu with **Add from library**. [P·snip] [help.openai.com Library](https://help.openai.com/en/articles/20001052-file-storage-and-library-in-chatgpt). Library storage is separate from attachment limits. Library is web-only for now (unverified: 403. The 2026-09-10 release note does say cloud sources roll out "on web; mobile support will follow"). [P·snip]
- **Sharing (2026-09-09):** "share files and folders with specific people (Viewer or Editor access) or your entire workspace". There is a "Shared with me" view. Files uploaded into a shared folder belong to the folder owner, and the uploader is recorded. If the owner removes your access, the file stays in their folder. [P, via the releases.sh mirror of OpenAI's release notes] [releases.sh](https://releases.sh/openai/chatgpt-release-notes.md); [chatgptaihub governance](https://chatgptaihub.com/chatgpt-library-sharing-governance-viewer-editor-folder-ownership-access-revocation-file-custody)
- **Cloud sources in the Library (2026-09-10):** Box, Dropbox and SharePoint join Google Drive, with "Add from Library". [S] same
- *Beats Claude [I]:* one place holds both what you uploaded and what the AI made, with folders and role-based sharing. The evidence for Claude's gallery shows own/shared lists and pinning, but not folders or uploads.

**Sites (hosted app artifacts)**
- Trigger by describing a site or by `@Sites`. The flow is **Preview, then Edit** (a "Describe website edits" field that takes screenshots or files), **Save a version** as a reviewable candidate (tied to Git commits for local projects), and **Deploy a version** to production. "Every deployment URL is a production deployment." [P] [learn.chatgpt.com/docs/sites](https://learn.chatgpt.com/docs/sites)
- Data: **D1** (10 GB) and **R2**. **Sign in with ChatGPT**, which passes visitor identity in the headers `oai-authenticated-user-email` and `-full-name`. Secrets live in site settings. **Traffic analytics** (unique visitors, pageviews). **Custom domains** via DNS, not in Enterprise at launch. Audience runs owner-only → invited → workspace → public. Editors can publish only after the owner's first deploy. A **Sites** library lives in the desktop app and at chatgpt.com/sites. [P] same
- Limits: no EEA, Switzerland or UK at launch; no payments; no data residency; permanent deletion; "no separate staging environment". [S] [playcode](https://playcode.io/blog/chatgpt-sites-explained). **Conflict:** the learn doc lists WebSockets as supported and playcode says they are not.
- *Beats Claude [I]:* the save-versus-deploy split, analytics, custom domains and platform identity. Juno's audit found no governance on public links, and the Sites audience ladder plus admin gating is a model for fixing that.

**Images 2.5 (2026-09-08)**
- OpenAI release note (2026-09-08): templates (Images → Templates); "On mobile, type @… select Sketch"; "**On mobile, open a generated image full-screen to edit it or add comments** to tell ChatGPT what you'd like to change"; share a prompt. [P, via the releases.sh mirror] [releases.sh](https://releases.sh/openai/chatgpt-release-notes.md); [testingcatalog](https://www.testingcatalog.com/openai-launches-chatgpt-images-2-5-with-faster-editing/) [S] (2026-09-09: "image comments support focused revisions"; it doesn't mention full screen)
- An image comment combines "a position with a written instruction", and "a location is not a pixel lock". Alongside comments the guide lists selection-based edits and direct written edits. *Correction:* Sketch is the separate sketch-to-image entry point, not an edit mode beside comments. The guide says button labels and positions may differ between mobile and web. [S] [atlascloud](https://www.atlascloud.ai/blog/tips/gpt-image-2.5-image-comments) (2026-09-16)

**Apps in ChatGPT: display-mode rules** [P] [Apps SDK UI guidelines](https://developers.openai.com/apps-sdk/concepts/ui-guidelines) (Apps SDK launched Oct 2025 [I])
- **Inline card**: shown before the model's reply; "Max 2 primary actions", "no deep navigation or multiple views", no nested scrolling.
- **Inline carousel**: 3–8 items, one CTA each, at most 3 lines of metadata.
- **Fullscreen**: the ChatGPT composer "remains overlaid, allowing users to continue 'talking to the app'". While a response streams, "the composer input 'shimmers'". When the model finishes, "an ephemeral, truncated snippet displays above the composer".
- **Picture-in-picture**: a persistent floating window that "stays fixed to the top of the display area" on scroll and must respond to input from the system composer. It "returns to an inline position and scrolls away" when the session ends. The page does not describe the animation between modes.
- *For Juno [I]:* this ladder (card → full screen with a live composer → PiP) is a better mobile story than a side panel, and it maps onto Mac and iPhone.

**Weaknesses and complaints**
- People who used Canvas as a long-document editor lost it ("you'll feel the loss of Canvas more"). [S] [theaicareerlab](https://theaicareerlab.com/blog/chatgpt-what-changed-june-2026)

- Output types are spread across Library, Sites, the Images view, writing blocks and Office add-ins. The gallery is unified for *files* but not for *Sites*, which have their own library. [I from the P sources above]

## 3. Motion: what beats Claude and Figma, and exemplary motion craft

**Baseline:** Figma already has manual keyframe tracks, animation styles, cubic and spring easing, HOLD, timelines and `export_video` (local `figma-use-motion` SKILL.md). Claude Slides have `data-transition` fade/push/magic and `data-build-in` fade/rise/pop. So motion **authoring** only has to beat those.

| Pattern | Who | Detail | Why it beats Claude/Figma | Source |
|---|---|---|---|---|
| **Stateful motion graph** | Rive | A "Graph" workspace where timeline animations become **states** (Idle, Hovered, Clicked) joined by **transitions**, "without the need for a complicated handoff" | Figma timelines are per frame and stateless, so interaction states need prototype wiring | [P] [rive.app docs](https://rive.app/docs/editor/state-machine/state-machine) |
| **Motion by prompt, on production** | Framer Agents | "staggered animations… each one fades in slightly after the previous", "parallax effect" | Claude Design has no motion model in the evidence, and Figma motion needs manual keyframes | [P] [framer.com/agents](https://www.framer.com/agents/) |
| **Streaming generation onto the canvas** | Stitch | "streams its work straight to the canvas" and can be steered mid-stream | Makes waiting a form of presence, and interruptible | [P] [blog.google](https://blog.google/innovation-and-ai/models-and-research/google-labs/stitch-updates/) (2026-05-19) |
| **Shimmer while the model writes** | ChatGPT apps, full screen | The **composer input "shimmers"** while a response streams. On completion "an ephemeral, truncated snippet displays above the composer" | A system-wide streaming signal on the composer, not per app | [P] [Apps SDK UI guidelines](https://developers.openai.com/apps-sdk/concepts/ui-guidelines) |
| **Card ↔ full screen ↔ PiP** | ChatGPT apps | PiP "stays fixed to the top" on scroll, and "returns to an inline position and scrolls away" when the session ends. *Correction:* the quoted "transitions between activated/pinned states" is not on the page (unverified), and the guidelines describe no animation between modes | A defined spatial model for one object across sizes; the motion is unspecified | [P] same |
| **Hot reload as agents finish** | Cursor | The running app updates live as each queued edit lands | Edits land in place, not as a remount | [P] [cursor.com/blog/design-mode](https://cursor.com/blog/design-mode) |
| **Frozen frame for annotation** | Cursor | Pauses the page so you can mark a moment in an animation | You can point at *motion*, which Claude comments and Figma comments can't do | [P] [cursor.com/docs](https://cursor.com/docs/agent/design-mode) |

## 4. Cross-cutting UX patterns worth stealing (and where they come from)

1. **Mode bar on the preview with single-key modes (S/T/D/C)**, draggable and minimisable, with its position remembered. *Lovable.*
2. **Comment → agent with the full thread, page, element and screenshot payload.** Resolved threads are hidden, and orphaned anchors are flagged. *Lovable; Paper (comments addressed to agents).*
3. **Queue edits while the agent works**, run as parallel subagents with hot reload in place. *Cursor; Lovable (visible prompt queue since 2026-02-05, toolbar queueing 2026-06-10, follow-ups mid-run 2026-09-08).*
4. **Frozen-frame annotation** for anything that moves. *Cursor.*
5. **Side-by-side iterations and managed directions (branches)**, with Shift-click on several outputs to apply one change to all. *Stitch.*
6. **Steer mid-generation.** *Stitch.*
7. **Voice as a first-class design input** (interviews, critiques, narrated edits with a mic that stays available while agents run). *Stitch, Cursor.*
8. **Suggest-then-approve queue**, top to bottom. *Notion.*
9. **AI edits land on a branch**, then merge. *Framer, v0.*
10. **Save a version versus Deploy a version**, with an audience ladder (owner → invited → workspace → public) and analytics. *ChatGPT Sites.*
11. **One library for uploaded and made things**: folders, Viewer/Editor sharing, Shared with me, cloud drives, "Add from Library" in the composer. *ChatGPT Library.*
12. **Output rail scoped to a context**: creation tiles above, a typed list below, several per type, usable while another generates. *NotebookLM Studio.*
13. **"Create" conversions between types** (doc → site, infographic, quiz, audio, slides). *Gemini Canvas.*
14. **Revise as a sibling, not an overwrite** (per-slide feedback → new deck). *NotebookLM.*
15. **Inline object → full screen with a persistent composer → PiP.** *ChatGPT apps; writing blocks.*
16. **Import foreign HTML as an editable design; embed code inside decks and whiteboards.** *Canva Code 2.0.*
17. **Re-apply the brand retroactively** across existing items. *Canva AI 2.0.*
18. **Portable design rules (DESIGN.md)** for import and export. *Stitch.*
19. **Capture live UI onto the canvas → iterate → PR.** *Subframe, Paper.*
20. **Free direct manipulation, paid AI.** Inline text edits are free within daily limits (100 per account, 2,000 per workspace), comments are free, and Select, Draw and sends cost credits. *Lovable.* For v0 this is (unverified): its docs say Design Mode's Apply sends the edits as a chat turn that makes a new version.

## 5. Weaknesses and complaints worth designing against

- **Removing a surface power users relied on:** ChatGPT Canvas's removal hurt long-document users. [S] [theaicareerlab](https://theaicareerlab.com/blog/chatgpt-what-changed-june-2026). *Juno: keep full-screen long-form editing when you consolidate.*

- **Availability:** Stitch "unavailable" threads with 10k+ views (Apr 2026). [S] [tech-insider](https://tech-insider.org/google-stitch-ai-design-tool-march-2026-update/)

- **Mobile gaps:** Gemini shared canvases are desktop-only [P]. NotebookLM mobile lacks some output types [S]. - **Fragmented "made things" even at OpenAI:** Library, a separate Sites library, image views and Office add-ins. [I]

## 6. What this means for Juno's merge (inferred, mapped to the Juno audit)

The Juno audit (`00-AUDIT-OVERVIEW.md` §4.5) lists seven paths for "Show me what Juno made", three for "Edit with AI" with separate histories, and five write paths. The references above suggest these moves. They do not overlap with what Claude and Figma already provide.

1. **One Library covering uploaded and made things** (ChatGPT) **plus a per-conversation output rail** (NotebookLM Studio). The rail gets creation tiles, a generating state you can work around, several per type, and a per-item pencil for revising parameters.
2. **Conversions as a first-class verb** (Gemini "Create"): Markdown doc → Slides, Site, Diagram or Design, each producing a **sibling** linked to its source.
3. **One comment system that is also the AI's inbox** (Lovable), across Docs, Slides, Design and HTML previews. It should send the full thread, the element and a screenshot, show an orphaned-anchor state, and make comments free while sends cost credits.
4. **A preview toolbar with S/T/D/C modes on every renderable artifact** (Lovable, v0, Cursor). Include frozen-frame drawing for animated artifacts, and **queueing** edits while the model runs.
5. **Suggest-then-approve as the default for AI edits to hand-edited artifacts** (Notion). This generalises Juno's existing Ask Juno preview-then-accept, and it directly prevents the audit's "revision silently reverts manual edits" problem. Pair it with **branch-on-AI-edit** for designs and sites (Framer, v0).
6. **Directions as branches on the Design canvas** (Stitch Agent Manager), with Shift-select across artboards to apply one change.
7. **Save versus Deploy for public artifacts**, plus an audience ladder and analytics (ChatGPT Sites). This closes the governance gaps the audit found (§1.8).
8. **An inline card → full screen with a persistent composer → PiP** as the spatial model on web, Mac and iPhone (ChatGPT apps and writing blocks), in place of a single fixed side panel.
9. **HTML import into the Design editor** (Canva Code 2.0). Any HTML artifact, or HTML from another AI, opens as editable design layers, and code blocks embed inside decks and designs.
10. **DESIGN.md import and export** next to Juno's own design-system record (Stitch).
11. **Motion:** a small **state-machine view** for interactive components (Rive) and **prompt-authored motion** that writes into Juno's existing motion tokens (Framer). Also streaming or shimmer presence for generation (Stitch, ChatGPT), with timings taken from Juno's own token system, since none are published.
