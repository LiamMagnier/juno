## EXTENSION POINT (for native/mac-cowork and anything else)

`NativeComposerTray(projects:apps:skills:media:leading:trailing:)` — `leading` and `trailing` are view slots drawn on the tray's one line.

- **Mac:** `ChatComposer.trayLeading` (before Project, on a new chat's line and before the media choices) and `ChatComposer.trayTrailing` (pushed to the end of the chat line) in `native/macOS/JunoDesktop/App/ChatComposer.swift`. Both are `EmptyView()` today. A chat model in an existing thread draws no tray unless `ChatComposer.trayShowsInThreads` is true (then the tray holds only the slots, plus a media model's choices).
- **Integrating native/mac-cowork (45bc128d7)**, per its STATUS "Moving the control into the composer tray": delete its `if` block after `+` in `ChatComposer.controlsRow`; put `ChatFolderControl(conversationID: fixedProjectID == nil ? model.selectedConversationID : nil)` in `trayLeading` (guarded `if !isPrivate && !voiceActive`, which the tray already enforces); set `trayShowsInThreads` to `true` because the folder belongs to a conversation as well as a draft; keep its draft hand-off in `dispatch`. For the tray's look, give its capsule `NativeComposerTrayPillStyle()` (28pt pill, no border) instead of its own capsule chrome.
- **iPhone:** pass `leading:`/`trailing:` where `JunoMobileComposer.tray` builds the tray.
- Style an item as a pill: `Button { } label: { JunoIconView(.folderOpen, size: 16); Text("Folder") }.buttonStyle(NativeComposerTrayPillStyle())`, or a `Menu` with `.menuStyle(.button)`, `.buttonStyle(NativeComposerTrayPillStyle())`, `.menuIndicator(.hidden)`. One pill per item; the line never wraps (it scrolls with fades when full).

## Web options not mapped

- **The frame chooser's stage** (the web's large morphing ratio preview with the output size in pixels): native uses the platform menu with each ratio's name and ratio, Auto first then tall → wide. Every ratio the web offers is there; the pixel readout (`framePixels`) is not.
- **The web's "Mac app" link** at the end of the chat line: omitted on native (owner's instruction); the trailing slot is where something native-relevant can go.
- **Parity quirk, kept on purpose:** on GPT Image 2.5 at 1:1, picking 4K moves the aspect to Portrait (2:3), which then caps resolution at 1K — the web's `applyParamChange` does exactly this (the first escape from 1:1 is 2:3). The native port matches the web; the fix belongs in `media-params.ts` (prefer an escape whose own rules allow the picked value), and both clients would follow.
