## A. Agent loop & runtime

### Model-visible tools (codex-rs/core/src/tools/spec_plan.rs, @ 2026-09-22)
- `exec_command` (unified exec, PTY-backed; params cmd, workdir, tty, yield_time_ms (default 10000ms), max_output_tokens (default 10000), shell, login, environment_id) + `write_stdin` (session_id, chars; empty = poll; yield 250ms–30s, empty polls 5s–300s). Unified exec on by default except Windows; when off, a one-shot exec_command. Legacy `shell` / `shell_command` names still referenced (`features.shell_tool` "Enable the default shell tool"). Background terminals = long-running exec sessions (`/ps`, `/stop`, `background_terminal_max_timeout`).
- `apply_patch` — FREEFORM tool with a Lark grammar (not JSON). Format:
  ```
  *** Begin Patch
  [*** Environment ID: <id>]
  *** Add File: path  (+lines)
  *** Delete File: path
  *** Update File: path
  [*** Move to: newpath]
  @@ [context header]
   context / -removed / +added lines
  [*** End of File]
  *** End Patch
  ```
  (codex-rs/apply-patch/src/parser.rs; lenient parsing on). Hooks can match it as `apply_patch`, `Edit`, or `Write`.
- `update_plan` — {explanation?, plan:[{step, status: pending|in_progress|completed}]}; "At most one step can be in_progress at a time." (plan_spec.rs)
- `view_image` (local image attach; `tools.view_image`), hosted `web_search` (Responses API hosted tool; modes cached/indexed/live/disabled), `request_user_input` (1–3 short questions, plan mode), `request_permissions` (ask for extra fs/network perms; turn or session scope), `tool_search` (deferred tool discovery), MCP resource tools `list_mcp_resources` / `list_mcp_resource_templates` / `read_mcp_resource`, MCP tools as `mcp__server__tool`.
- Multi-agent: `spawn_agent`, `send_input`, `resume_agent`, `wait_agent`, `close_agent` (v2 adds `followup_task`, `list_agents`, `interrupt_agent`, `send_message`). Built-in agent roles: `default`, `worker`, `explorer`; custom agents = TOML in `~/.codex/agents/` or `.codex/agents/` (name, description, developer_instructions + any config keys). `/agent` (CLI) to switch threads. Subagents inherit sandbox/permission mode. (https://learn.chatgpt.com/docs/agent-configuration/subagents.md)
- Misc gated: `get_context_remaining`, `new_context_window` (token budget feature), `current_time`, `sleep`, `request_plugin_install`, `list_available_plugins_to_install`, "code mode" (`exec`/`wait`, under development), image generation (namespace tool, gated).

### Sandbox
- macOS: Seatbelt via `sandbox-exec -p <profile>`; curated platform policy for restricted reads. Linux/WSL2: **bubblewrap (`bwrap`) + seccomp** (moved from Landlock in CLI 0.115; WSL1 dropped). Native Windows: own sandbox (`windows.sandbox = unelevated|elevated`, private desktop). `codex sandbox macos|linux|windows [--permissions-profile] CMD` to test (aliases `seatbelt`, `landlock`). (https://learn.chatgpt.com/docs/agent-approvals-security.md, /docs/sandboxing.md)
- Network OFF by default for local commands (`sandbox_workspace_write.network_access = true` to enable); optional `features.network_proxy` domain allow/deny rules (deny wins; `*.x`, `**.x`; local/private blocked unless explicit). Cloud: setup phase has network, agent phase offline by default; secrets removed before agent phase.
- Protected read-only inside writable roots: `.git` (and resolved gitdir), `.agents`, `.codex`.
- `sandbox_mode`: `read-only` | `workspace-write` (default low-friction) | `danger-full-access`.
- `approval_policy`: **`on-request` | `never` | `{ granular = { sandbox_approval, rules, mcp_elicitations, request_permissions, skill_approval } }`**. **`untrusted` is RETIRED** (can prevent startup; use `[projects."/path"] trust_level = "untrusted"` for the strict behavior). `on-failure` is not listed in current docs/reference (removed earlier; exact date unverified).
- `approvals_reviewer`: `user` (default) | `auto_review` (reviewer subagent, "guardian"; policy at codex-rs/core/src/guardian/policy.md; statuses Reviewing/Approved/Denied/Aborted/Timed out + risk level; fails closed; `/approve` retries one denial).
- Beta permission profiles: `default_permissions = ":read-only" | ":workspace" | ":danger-full-access" | <custom>` + `[permissions.<name>]` filesystem/network rules; don't mix with sandbox_mode.
- Command rules (execpolicy, experimental): Starlark-ish `prefix_rule(pattern=[...], decision="allow|prompt|forbidden", justification, match, not_match)` in `rules/*.rules` next to config layers; "don't ask again" writes `~/.codex/rules/default.rules`; "Smart approvals" propose prefix rules. (https://learn.chatgpt.com/docs/agent-configuration/rules.md)
- Launch defaults: git repo → Auto (workspace-write + on-request); non-VCS folder → read-only; may start read-only until you trust the dir.

### AGENTS.md

## App-server essentials (https://learn.chatgpt.com/docs/app-server.md)
- Primitives: Thread > Turn > Item. initialize/initialized handshake; thread/start|resume|fork|read|list|archive|unarchive|delete|name/set|goal/set|compact/start|rollback(deprecated)|shellCommand|backgroundTerminals/*; turn/start|steer|interrupt; review/start; command/exec*; model/list; skills/list; plugin/*; mcpServerStatus/list; config/read|value/write|batchWrite; fs/*.
- Notifications: thread/started, turn/started, turn/completed (completed|interrupted|failed), turn/diff/updated (aggregated unified diff), turn/plan/updated, thread/tokenUsage/updated, hook/started|completed, item/started, item/completed, item/agentMessage/delta, item/plan/delta, item/reasoning/summaryTextDelta|summaryPartAdded|textDelta, item/commandExecution/outputDelta.
- Item types: userMessage, agentMessage (phase commentary|final_answer), plan, reasoning, commandExecution {command,cwd,status,commandActions,aggregatedOutput,exitCode,durationMs}, fileChange {changes:[{path,kind,diff}]}, mcpToolCall, dynamicToolCall, collabToolCall, webSearch {query, action search|openPage|findInPage}, imageView, enteredReviewMode/exitedReviewMode, contextCompaction.
- Server->client requests: item/commandExecution/requestApproval, file change approval, tool/requestUserInput, item/permissions/requestApproval, mcpServer/elicitation/request; decisions accept|acceptForSession|decline|cancel|acceptWithExecpolicyAmendment; network approvals grouped by host/protocol/port.
- Errors codexErrorInfo: ContextWindowExceeded, UsageLimitExceeded, HttpConnectionFailed, ResponseStreamConnectionFailed, ResponseStreamDisconnected, ResponseTooManyFailedAttempts, BadRequest, Unauthorized, SandboxError, InternalServerError, Other.
- Transports: stdio JSONL (default), ws://, unix:// ; `codex app-server generate-ts` / JSON schema for bindings (per blog). Desktop app bundles pinned codex binary.
