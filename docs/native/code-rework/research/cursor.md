# Cursor (Anysphere): competitor audit notes
Research date: 2026-09-22. Sources are mainly primary: cursor.com/docs (.md versions via cursor.com/llms.txt), cursor.com/changelog (all 14 pages, 1.0 Jun 2025 to Sep 2026), cursor.com/blog, archived docs (Wayback, Oct/Nov 2025), and official screenshots from the changelog, blog and docs. Where only forum.cursor.com staff replies (Cursor employees) or community posts were available, the note says so. "Unverified" means I could not confirm it.

Current state: the latest client in forum reports is **3.20.17** (forum /t/171475, Sep 13 2026). 3.17 is referenced Aug 26 and 3.19.7 in early Sep. Cursor has **two desktop surfaces**: the classic **IDE** (VS Code fork, Agent side panel) and the **Agents Window** (codename "Glass", Cursor 3, Apr 2 2026). They have separate settings screens and themes.

## A. Agent loop and runtime

### A1. Harness and tools
- Docs: "An agent is built on three components: Instructions (system prompt + rules), Tools, Model… Cursor… tun[es] instructions and tools specifically for every frontier model." "There is no limit on the number of tool calls." https://cursor.com/docs/agent/overview.md
- Current documented tool families: **Search files and folders** (name search, directory read, grep), **Web** (search), **Fetch Rules**, **Read files** (including images: png/jpg/gif/webp/svg), **Edit files**, **Run shell commands** (first terminal profile), **Browser**, **Image generation**, **Ask questions** (non-blocking: the agent keeps working while it waits), plus MCP, Task (subagents), Await (3.0), conversation search (2.5), **Canvas** (/canvas), todo list (1.2), plan create/update tools (Plan Mode).
- Hook matcher tool names reveal internal names: `Shell`, `Read`, `Write`, `Grep`, `Delete`, `Task`, `MCP:<tool>`; subagent types `generalPurpose`, `explore`, `shell` (https://cursor.com/docs/hooks.md).
- Archived Nov 2025 tools page (https://web.archive.org/web/20251101/https://cursor.com/docs/agent/tools) listed: Read File, List Directory, Codebase (semantic search over the indexed codebase), Grep, Search Files (fuzzy), Web, **Edit & Reapply**, **Delete File** ("can be disabled in settings"), Terminal, MCP toggle. Advanced options: **Auto-apply Edits, Auto-run, Guardrails (allow lists), Auto-fix Errors** (lint).
- **Semantic "Codebase Search" is gone as of mid-2026.** Search = **Instant Grep**: "a custom search engine that outperforms ripgrep on large codebases", full regex, word boundaries, index built locally (https://cursor.com/docs/agent/tools/search.md). The Explore subagent handles broad search.
- CLI web tools: **WebFetch, WebSearch** with domain allowlisting; known-safe URLs (Cursor docs) auto-approved (CLI Feb 18 2026).

### A2. How edits are applied
- Edits are **written to disk immediately**: "Agents can modify workspace files without approval, except for configuration files. Changes save immediately to disk." (https://cursor.com/docs/agent/security.md).
- Mechanisms: a **Search & Replace** edit tool plus a specialized **Apply** model ("Apply is a specialized Cursor model that takes code generated by chat and integrates it into your files… Apply does not generate code itself"; archived docs.cursor.com/en/agent/apply, Sep 2025). 1.3 changelog: "Search & Replace edit latency has been reduced by 25% and Apply edits by almost 11%". The 2.3 fix mentions an "old_str replace failed error". afterFileEdit gives `old_string` (CLI Jan 8 2026). **Edit & Reapply** is a tool.
- **Review**: pending diffs with **Keep/Undo** per hunk (inline in the editor) and **Keep All / Undo All** (⌘⏎ / ⇧⌘⌫). A review pane lists files; clicking a file jumps to its diff; split/unified toggle (2.3). Since 2.5, **inline diffs are off by default** (diffs only in the review panel) behind a toggle. Committing auto-accepts pending diffs. Archived review doc: "A floating review bar appears at the bottom of your screen" with accept, reject, next file; "Accept all / Reject all".
- Agents Window: a **diffs view** ("9 Uncommitted Changes +2392 -1", per-file rows with New badge, revert and stage checkbox; a **Commit & Create PR** split button); PR view (Changes PR #N, Draft chip, branch → main, "Mark as Ready", "7 Files Changed +93 -28", "560 unmodified lines" collapsed). Seen in the Cursor 3 blog video thumbnails.

### A3. Agent Review (local), Bugbot (PR) and Security Review
- **Agent Review** (2.1, Nov 2025): a review of local diffs. Triggers: automatic on commit, `/agent-review`, or the Source Control tab (full branch vs main). Depth **Quick | Deep**. Reads `BUGBOT.md`. https://cursor.com/docs/agent/agent-review.md. Settings (IDE, Git & PRs > Agent Review, Aug 2026 screenshot on forum /t/169461): **Start Agent Review on Commit**, **Include Submodules in Agent Review**, **Include Untracked Files in Agent Review**, **Default Approach (Quick/Deep)**. Staff also mention "Auto-Run on Agent Finish". Older (Oct 2025): Auto-run on commit, Only show notification if bugs are found, Hide all Agent Review features.
- `/review` (3.7): choose Bugbot and/or Security Review before pushing. `/review-bugbot` stores the git patch-id, so PR Bugbot skips an identical diff.
- **Bugbot** (1.0, Jun 2025): PR comments with "Fix in Cursor"/"Fix in Web", manual trigger `cursor review`/`bugbot run`, **incremental reviews**, PR summaries (in description, as comment, or off), **effort levels** (Low/Default/High/Smart), rules (Team → `.cursor/BUGBOT.md` nested → learned → manual; `@cursor remember [fact]`), **Autofix** (spawns a cloud agent, Feb 2026), MCP (Apr 2026), ~90s reviews powered by Composer 2.5 (Jun 2026). Project `.mdc` rules do **not** apply to Bugbot. https://cursor.com/docs/bugbot.md

### A4. Run modes, approvals and sandbox (https://cursor.com/docs/agent/security/run-modes.md)
- Location: **Settings > Agents > Approvals & Execution**.
- Current modes (3.6+): **Auto-review** (default: allowlisted calls run, other shell commands run in the sandbox when possible, and the rest go to a classifier), **Allowlist** (optionally with sandboxing), **Run Everything**. History: before 3.5 the modes were **Run in Sandbox, Ask Every Time, Run Everything** (archived Nov 2025 docs call the setting "Auto-Run Mode" under Settings → Cursor Settings → Agents → Auto-Run). 3.5 deprecated Ask Every Time (use an empty Allowlist). Auto-review shipped in 3.6 on May 29 2026.
- **Auto-review classifier**: a small model (Claude 4.5 Haiku or GPT-5.4 Mini) that is agentic (can ReadFile/Grep/Glob/ListDir before deciding) and runs in the same RPC stream as the parent. On a block it returns an explanation to the parent agent, which picks another path; the user is prompted only if the agent insists. Stats: blocks ~4% of reviewed actions, and ~7% of chats see at least one interruption (https://cursor.com/blog/agent-autonomy-auto-review, Jun 11 2026). Steered by `permissions.json` `autoRun.allow_instructions`/`block_instructions` in plain English (~/.cursor and <project>/.cursor, merged; team config overrides).
- **permissions.json**: `mcpAllowlist` ("server:tool", wildcards), `terminalAllowlist` (prefix semantics, `npm:install*` arg globs), `autoRun`. It overrides the in-app allowlists, which then become read-only and hide "Add to allowlist". Precedence: team admin > permissions.json > IDE UI. https://cursor.com/docs/reference/permissions.md
- **Sandbox**: macOS Seatbelt via `sandbox-exec` with a runtime-generated profile (from 1.7 beta; GA by default in 2.0); Linux Landlock + seccomp (Dec 2025); Windows runs the Linux sandbox in WSL2. Defaults: workspace read/write; protected paths (`.git/config`, `.git/hooks`, `.vscode`, `.cursorignore`, `.code-workspace`, `.cursor/*` except rules/commands/worktrees/skills/agents); network blocked unless allowed; /tmp writable. Network modes: **sandbox.json Only / sandbox.json + Defaults (default) / Allow All**. Env vars `CURSOR_SANDBOX=seatbelt`, `CURSOR_AGENT`. "Sandboxed agents stop 40% less often"; about a third of requests run sandboxed (https://cursor.com/blog/agent-sandboxing, Feb 18 2026). Harness change: Shell tool results explicitly name the sandbox constraint that caused a failure and suggest escalation.
- Sandbox failure prompt (archived Nov 2025 terminal docs): **Skip** (let the agent try something else) / **Run** (without sandbox) / **Add to allowlist**.
- **Other protections**: **Browser Protection**, **File-Deletion Protection** (including `rm`), **External-File Protection** (outside the workspace). Earlier: **Dotfile Protection** (removed in 2.5), **MCP Tool Protection** (admin), "Allow Git Writes Without Approval", "Auto-Run Network Access". Config files (workspace settings) always need approval.
- MCP: "All MCP connections need your approval… each tool call still needs individual approval" unless allowlisted. MCP approval card buttons: **Skip / Always Run / Run** (forum /t/165328, Jul 2026; staff note that MCP args are currently not shown on the approval card, a regression).
- Browser tool approval modes: Manual approval / Allow-listed actions / Auto-run, plus allow and block lists (https://cursor.com/docs/agent/tools/browser.md).
- Workspace trust is supported but **off by default**.
- The per-command "…" menu in a terminal tool card offers Auto-Run options **Allowlist / Auto-review / Run Everything / Copy Command** (forum screenshot /t/169478, Aug 2026).
- Cloud agents do not use run modes (their own VM; they never ask).

### A5. Modes
- Current: **Agent, Ask (read-only), Plan, Debug**, plus **Custom Modes** (Aug 2026: any skill pinned as a mode). Switch with **Shift+Tab** (rotate) or **⌘.** (mode menu). "Each mode uses its own context, so switching modes starts a fresh context window." (https://cursor.com/help/ai-features/agent.md). The agent can propose mode switches (2.4).
- Old Custom Modes (2025): Settings → Chat → Custom Modes with tool selection and instructions; examples Learn/Refactor/Debug. Mode-specific settings: Agent had "Auto-run and Auto-fix Errors", Ask had "Search Codebase" (archived Oct 2025 modes page). Removed in 2.1 and replaced by commands.
- **New Custom Modes** (https://cursor.com/docs/agent/prompting.md): pick a skill from `/` and press **⌥Enter** or choose "Use as Mode". The skill stays in context every turn and shows as a **badge** in the input (SKILL.md frontmatter `icon` [code, terminal, bug, git-branch, book-open, beaker, shield, rocket; default lightning] and `color` [default, green, cyan, blue, purple, magenta, orange, yellow, red, brand]).
- **Plan Mode** (1.7; https://cursor.com/docs/agent/plan-mode.md): asks clarifying questions (interactive Q&A UI, 2.1, with multiline answers), researches, and writes a **Markdown plan file with file paths, code references and to-dos**, editable inline or as a file (virtual file tab). Plans are stored in the home directory by default; "Save to workspace" moves them to `.cursor/plans/`. **Build** button; build in foreground/background/cloud; **Build in Parallel** (3.3); send selected to-dos to new agents (2.2); inline Mermaid (2.2); plan with one model and build with another. Plan content feeds autocomplete (2.6). Cursor suggests Plan Mode automatically for complex prompts.
- **Debug Mode** (2.2): hypotheses, instrumentation that logs to a local debug server in a Cursor extension, the user reproduces, log analysis, a targeted fix, then instrumentation cleanup. https://cursor.com/docs/agent/debug-mode.md
- `/goal <objective>` (Aug 2026) for long-lived objectives; `/loop` for recurring or self-paced wakeups.

### A6. To-dos, queue, steering, interrupt
- To-dos (1.2): created automatically for complex tasks, with dependencies, updated live, and shown in chat as a card ("6 of 8" current item; "7 of 8 To-dos" collapsible; a pinned header "4 of 4 To-dos Completed").
- Queue: Enter queues the message while the agent works; queued messages show under the active task and can be drag-reordered and edited.
- Steering: "Send now" or **Enter twice** delivers the message at the **next tool call** (non-interrupting; Aug 19 2026). Setting: **Settings → Agents → Conversation → New Messages: Queue | Steer**. The per-message override is Ctrl/⌘+Enter (staff, forum /t/172313, Sep 19 2026). Older IDE setting "Queue messages: Send after current message | Stop & send right away".
- Interrupt: **Stop** button (the send button becomes a black stop square while running); ⌘⇧⌫ cancels generation. In the CLI, Enter steers, a second Enter interrupts, and Ctrl+C pauses a goal. The CLI distinguishes "Cancelled" from "Interrupted".

### A7. Context management
- Auto-summarization near the window limit; `/summarize` (1.6). A **context ring** next to the input; clicking it opens a **breakdown tray** (System prompt, Tools, Rules, Skills, MCP, Subagents, Summarized conversation, Conversation), with hover highlighting (3.3). There is also a context report canvas with a "Debug with Agent" button (Jun 2026). The `preCompact` hook reports usage %, tokens, and messages to compact. Older file condensation states: Condensed / Significantly condensed / Not included (archived summarization docs).
- Dynamic context discovery: MCP tools and skills load only when needed (2.4).

### A8. Checkpoints
- Created automatically before significant changes; stored **locally, separate from Git**. You can click a checkpoint in the timeline to **preview**, then restore. "Restore Checkpoint" is on previous requests, and hovering a message shows a + button. Restoring reverts files only (messages stay); forking a chat from a message truncates the conversation. https://cursor.com/docs/agent/overview.md. Plan help mentions a "Revert" then "Confirm" flow.

### A9. Subagents (https://cursor.com/docs/subagents.md)
- Built-ins: **Explore** (faster model, parallel searches), **Bash**, **Browser**. Foreground (blocking) or background. Nesting since 2.5 (one level: children of subagents can't spawn more). Custom subagents live in `.cursor/agents/*.md` (also `.claude/agents`, `.codex/agents`, user `~/.cursor/agents`) with frontmatter `name, description, model (inherit | id[effort=high,context=300k]), readonly, is_background`. Invoke explicitly with `/name`. **Isolated copies**: "each in its own environment" gets its own git worktree or cloud VM and branch; the parent merges. Resume by agent ID. Background output goes to `~/.cursor/subagents/`. Explore model setting: specific model / inherit / disabled (3.3; Settings → Agents → Subagents).
- `/multitask` runs async subagents instead of queueing. **Cloud subagents**: `/in-cloud`, `/autopilot` (PR babysitting).

### A10. Parallel agents and worktrees (https://cursor.com/docs/configuration/worktrees.md)
- 2.0: up to 8 agents on one prompt (multi-model), each in its own worktree or remote machine; **judging** recommends a winner (2.2). 3.0 editor: `/worktree`, `/best-of-n sonnet,gpt,composer <task>`, `/apply-worktree`, `/delete-worktree`. Agents Window: native worktrees with "move any branch into your local foreground with one click" (3.2).
- `.cursor/worktrees.json`: `setup-worktree`, `setup-worktree-unix`, `setup-worktree-windows` (command array or script path; `$ROOT_WORKTREE_PATH`). Cleanup settings `cursor.worktreeCleanupIntervalHours` (6), `cursor.worktreeMaxCount` (25 per machine). CLI `--worktree [name]` goes under `~/.cursor/worktrees/<repo>/<name>`. Worktrees are disabled for multi-root workspaces.

### A11. Cloud agents (formerly Background Agents)
- History: early access ~May 2025; GA 1.0 (Jun 2025); Slack 1.1; GitHub @Cursor 1.4; Linear 1.5; renamed 2.0; computer use Feb 2026; Jira and MS Teams May 2026; iOS Jun 2026.
- Isolated VMs with a full dev environment. Environment options: **agent-led setup** (under 10 min, visible in a shared terminal), **snapshot**, or **Dockerfile** via `.cursor/environment.json` (`{"snapshot": "...", "install": "npm install"}` or `{"build": {"dockerfile", "context"}, "install", ...}`, plus start commands and terminals). **Builds** (Aug 2026) pre-warm environments and fall back to the last good build. Secrets tab; IAM roles; Tailscale; egress allowlists. Artifacts: screenshots, videos, logs; remote desktop takeover. https://cursor.com/docs/cloud-agent.md and https://cursor.com/docs/cloud-agent/setup.md
- Triggers: desktop ("Cloud" in the dropdown under the input), cursor.com/agents, iOS/iPad, Slack @cursor, GitHub/Bitbucket @cursor comments, Linear, Jira, Teams, API/SDK, and **Automations** (schedules, Slack emoji, GitHub events, PagerDuty, webhooks). CLI `&` prefix hands off to the cloud. Agents Window: move local↔cloud; **Remote Control** from a phone (Settings → Agents; "Keep this computer awake").
- **Projects** (Sep 10 2026): a coordinator agent that "doesn't write code itself", delegates to many agents, keeps shared context files synced across machines, and has **Subscriptions** (a "Listening" pill above the input).

### A12. Rules, AGENTS.md, skills, commands, memories
- Rules (https://cursor.com/docs/rules.md): **Project** `.cursor/rules/*.mdc` (a `.md` file is ignored; subfolders and nested `.cursor/rules` allowed), **User** (Customize → Rules; stored on the account), **Team** (dashboard; "Enforce this rule"; glob support), **AGENTS.md** (root and nested; nested files take precedence). Types via frontmatter: **Always Apply** (`alwaysApply: true`), **Apply Intelligently** (description), **Apply to Specific Files** (globs), **Apply Manually** (@-mention). Precedence: Team → Project → User. Create with `/create-rule` or Customize → Rules → Add Rule. The CLI also reads `CLAUDE.md`. `~/.cursor/rules` is included (2.1). User rules don't apply to Inline Edit (⌘K).
- **Skills** (2.4): `.agents/skills`, `.cursor/skills`, and `~/...` equivalents. SKILL.md frontmatter: `name, description, paths, disable-model-invocation, icon, color, metadata`. Built-in skills: /automate, /autopilot, /canvas, /create-hook, /create-rule, /create-skill, /create-subagent, /cursor-blame, /loop, /migrate-to-skills, /review, /review-bugbot, /review-security, /sdk, /shell, /split-to-prs, /statusline, /update-cli-config, /update-cursor-settings. `/` attaches a skill to one message and ⌥Enter makes it a mode.
- **Commands**: `.cursor/commands/*.md` (1.6) and Team Commands (2.0). Migration to skills via `/migrate-to-skills` (commands become skills with `disable-model-invocation: true`). Still listed in Customize.
- **Memories**: beta in 1.0 (Jun 2025, "Settings → Rules"), GA 1.2 (Jul 2025), **removed in 2.1** (Nov 2025; export to .mdc). The 2.x Settings section was "Rules, Memories, Commands" (staff forum /t/144057). Successors: Automations' memory tool (Mar 2026), Projects' shared context (Sep 2026), Bugbot learned rules.
- **Customize** page (3.9, Jun 2026): one place for plugins, skills, MCPs, subagents, rules, commands and hooks, filtered by user/team/workspace, with a marketplace leaderboard. https://cursor.com/docs/customize-cursor.md

### A13. Hooks (https://cursor.com/docs/hooks.md)
- `hooks.json` (`{"version":1,"hooks":{event:[{command,type:"command"|"prompt",timeout,matcher,loop_limit,failClosed}]}}`) at Enterprise (MDM path) > Team (dashboard) > Project `.cursor/hooks.json` > User `~/.cursor/hooks.json`. The files are watched and reloaded. They run in parallel with merged responses (deny > ask > allow).
- Events: **sessionStart, sessionEnd, preToolUse, postToolUse, postToolUseFailure, subagentStart, subagentStop, beforeShellExecution, afterShellExecution, beforeMCPExecution, afterMCPExecution, beforeReadFile, afterFileEdit, beforeSubmitPrompt, afterAgentResponse, afterAgentThought, preCompact, stop** (with `followup_message` for loops, default loop_limit 5), Tab hooks **beforeTabFileRead, afterTabFileEdit**, and the app hook **workspaceOpen** (returns pluginPaths).
- Exit code 2 means deny. Other failures fail open unless `failClosed`. **Prompt-based hooks** are evaluated by an LLM (`{ok, reason}`). Claude Code hooks compatibility is available.

### A14. MCP, plugins, browser, canvases
- MCP: one-click install and OAuth (1.0), elicitation (1.5), Resources (1.6), **MCP Apps** (interactive UI in chat, 2.6), dynamic loading (2.4). Plugins bundle skills, subagents, MCP servers, hooks and rules (2.5), with team marketplaces.
- **Browser**: tools Navigate, Click, Type, Scroll, Screenshot, Console Output, Network Traffic. Logs are written to files the agent greps. Browser state (cookies, localStorage, IndexedDB) persists per workspace. It runs as a web view controlled via an MCP server extension with per-session tokens. Multiple tabs (2.3). **Design Mode** (⌘⇧D) in the Agents Window browser: click, multi-select, draw over a frozen frame, and voice. The agent receives xpath, component, computed styles, fiber props and a screenshot (https://cursor.com/docs/agent/design-mode.md; blog Jun 5 2026 by Erik Nilsson, Ian Huang & Ryo Lu).
- **Canvases** (Apr 2026): agent-generated interactive React artifacts built from first-party components (tables, boxes, diagrams, charts, diffs, to-dos). They render beside the chat as durable side-panel tabs, can be shared as read-only links, and have Design Mode (https://cursor.com/docs/agent/tools/canvas.md).

### A15. CLI (https://cursor.com/docs/cli/overview.md)
- `agent` (formerly `cursor-agent`). Modes Agent/Plan/Ask (plus /debug). `-p` print mode with `--output-format json|text`. `--resume`, `--continue`, `agent ls`. `& prefix` sends to the cloud. `--worktree`. `/sandbox`. `agent acp` (Agent Client Protocol server; used for JetBrains). Masked sudo prompt. Config `~/.cursor/cli-config.json` (approvalMode `allowlist|auto-review|unrestricted`, `notifications`, `display.showThinkingBlocks`, attribution, etc.). Permissions `Shell(ls)` allow/deny. Slash commands include /model, /run-everything, /plan, /ask, /debug, /goal, /summarize, /rewind, /fork, /resume, /mcp, /plugin, /config, /statusline, /sandbox, /vim, /show-thinking. Mermaid is rendered as ASCII (Ctrl+O toggles source). Review with Ctrl+R.

## D. Motion and visual design
- **Visual language (official screenshots, 2025–26)**: very restrained, neutral and monochrome. Light theme uses a warm off-white canvas, a slightly darker grey sidebar, hairline borders and rounded cards (~8–12px). Primary actions are **solid black pills or circles** (mic/stop, "Commit & Create PR", "Mark as Ready"); secondary actions are plain grey text buttons (Undo All, Keep All). Blue is reserved for confirm or apply in pickers (Done, Apply All in 2.0). Diff colours are soft pastel green/red line backgrounds with a coloured gutter bar. Metadata is small grey text (branch names, "Worked for", +/− counts in green/red). Dark theme (settings): near-black panels, grouped rounded setting cards with a title plus grey description on each row, green iOS-style toggles, small grey section headers. Icon set: thin line icons (Lucide-like; names such as git-branch, beaker, rocket appear in the skill icon list).
- Density: user-selectable (Compact/Balanced/Detailed). The default Agents Window hides tool noise behind "Worked for…/Explored/Thought" summary rows. The design goal (Cursor 3 blog): "brings clarity to the work agents produce, pulling you up to a higher level of abstraction, with the ability to dig deeper when you want."
- Typography: the app UI uses the system UI font by default and is configurable (Appearance → Typography → UI Font Family). 3.1 enabled macOS anti-aliasing. Code is monospace. The marketing site's brand faces (from cursor.com CSS) are **CursorGothic** (sans), **cursorDisplay**, **cursorMono/berkeleyMono**, and **EB Garamond** (serif). Whether the app bundles CursorGothic is unverified.
- Motion: status-text shimmer on "Planning next moves"/"Generating…" (user-described; unverified spec); 1.5 "border animation" on a blocking terminal; streaming edits (3.1 "cutting dropped frames by ~87%"); smooth long-chat scrolling fixes; the 3.0 scroll-to-bottom button. There is no published motion spec.
- Design writeups: https://cursor.com/blog/design-mode (Jun 5 2026, Erik Nilsson, Ian Huang & **Ryo Lu**, Head of Design): "UI work tends to be spatial"; element identity plus a screenshot as context; "shrinking the distance between what you see and what the agent understands". https://cursor.com/blog/cursor-3 (Apr 2 2026): "we took that a step further by building this new interface from scratch, centered around agents"; codename "Glass" (seen in the codebase paths `vscode/src/vs/glass/...` in the official video thumbnail and in the setting-name forum threads). Secondary: Ryo Lu interviews (a16z podcast https://a16z.com/podcast/ryo-lu-cursor-ai-turns-designers-to-developers/ ; https://creatoreconomy.so/p/design-to-code-with-cursor-head-of-design-ryo-lu , Dec 2025), which describe 2.0 as "Agent becomes the center… files move into the background" and unifying features "under a single core concept: Agent, expressed through different modes". These are secondary and paraphrased by third parties.
