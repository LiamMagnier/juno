## Cross-cutting requirements and dependency order

- **Routines are substantial existing infrastructure, not a missing scheduler.** `WorkSchedule` includes IANA timezone, missed-run policy, pinned run configuration, unattended approval policy, budgets, concurrency, notifications, retries and dispatch lease. `src/lib/work/schedule.ts` and `triggers.ts` cover schedule/email/calendar/topic/connector/folder/API trigger shapes; `tests/work-schedule.test.ts` and route/cadence tests exist. Trigger shape support is not proof each connected source delivers real events; limits are documented in `TRIGGER_OPTION_LIMITS`. Next vertical: one real trigger→named agent→approval→resume→notification→DST/restart history flow using the current dispatcher.
- **Reliability already has real building blocks.** Work claim/checkpoint/park/finish writes fence lease owners; Research leases and durable events, Code session checkpoints and scheduler deduplication exist. Accept process death/network timeout/stale owner/external-write idempotency on actual persistence before saying long-running recovery is complete. A Rooms turn cap is not a durable team scheduler.
- **Observability/cost exist in separate domains.** Work audit/budget/preflight/notifications, agent spending caps, Research spend windows/cost and Code usage receipts exist (`src/lib/work/{audit,budget,preflight-cost}.ts`, `src/lib/agents/budget.ts`, `src/lib/research/spend-windows.ts`). Next vertical: correlate run/worker/tool/approval/artifact events across one real task with redacted traces and per-worker hard budget. Do not invent precise compute cost when the host reports none.
- **Evaluation is not automatically E2E.** `scripts/eval-juno.ts` advertises objective end-to-end tasks but inspected tasks invoke pure parsers/domain functions. `scripts/memory-bench.ts` is useful scoped evaluation. Build provider/persistence/browser replayable acceptance jobs that record success, model, latency, actual spend, retries, citations and outputs; keep domain checks separately named. The current Memory milestone record names `tests/tool-search-chats.test.ts`, absent in this checkout; reconcile that reported command before relying on its count. No current competitive superiority conclusion follows from those script names.
- **Design/activity requirements remain semantic.** Current Research uses real states/evidence, stationary Continuum and native/web tokens. Preserve homepage/Memory editorial hierarchy across follow-up workflows. Named agent speakers/ownership/handoffs should replace internal worker labels while technical data stays behind disclosure. Reduced Motion is a separate acceptance path.
- **Owner decisions cannot be inferred from code.** Provider resale/retention/data region terms, Alevr name/trademark, privacy notices and store/signing/distribution acceptance need documented owner decisions. No action in this audit resolves legal or infrastructure blockers.

The next locally actionable product vertical is **Rooms client continuation and visible speakers**, over its existing bounded backend, with two agents, reload and duplicate-turn prevention. In parallel, the security-dependent path is **one scoped credential broker grant → accepted takeover → Teach dry-run → pinned Routine**. Neither requires another scheduler, another memory store or another desktop implementation.
