## Motion idea: a path continues

Continuum is the selected master-logo direction. Its folded paths and open channels symbolize understanding becoming action. Motion passes attention between adjacent paths or settles a meaningful object into place. It never adds random spectacle to the application. The same continuity, timing, optical weight and tonal response unite Chat, Orbit and Code, even though their workflows differ.

Inherit the existing V3 timing: press 70, fast 120, exit 160, base 220, slow 360 and rare emphasis 560 ms. Use the actual existing curves; do not introduce a second animation vocabulary. Keyboard effects remain immediate. Consequential approval arming/semantics are unchanged.

## Thinking indicator: the actual Continuum mark

- Place an optically reviewed 16–20 px Continuum mark beside the real live-action label, in the relevant reply/work row. Do not use an unrelated spinner, orb or Claude's shape. A mark that appears only in the active row is not a decorative avatar on every reply.
- Prototype a **tonal path handoff**: one of the existing filled paths shifts gently toward presence ink, then passes attention to the next existing path. Preserve silhouette/counterspace and keep the total size stationary. No whole-logo spinning, jumping, particle emission, glow, faux typing dots or generic shimmer sweep.
- Proposed event response: 220 ms tone transition, 70 ms stagger between adjacent path segments, one brief pass on thinking-start. New real reasoning/activity batches may request another pass, coalesced so high-frequency deltas cannot restart it more often than every 1.6 seconds. These are prototype tuning values, not a requirement to animate each token.
- When there are no new events, the mark holds a quiet stable pose. The label and real elapsed time may show continued work. Do not manufacture progress percentages or pretend animation measures reasoning depth.
- Show Thinking only during actual model reasoning/processing. For a tool, use the actual phase: Reading files, Running Python, Searching, Waiting for your answer. The mark follows the truthful work row; the state text changes from actual runtime events.
- Completion settles once, then yields to the result; error/interruption/waiting becomes a static state with an understandable label and recovery action. The logo does not celebrate an unverified outcome.
- Preserve inherited pending-indicator delay/minimum visibility (200/400 ms) where applicable; avoid flashing the mark on trivial operations. Hide/cancel animation when the row/window is not visible. Reduced Motion uses the static mark and text, with a brief permitted fade only.
- The mark is decorative when adjacent state text supplies meaning. Announce semantic phase changes through the existing accessible live-region strategy, not each segment or reasoning delta. Color/animation are never the sole state signal.
- This is a visible status treatment, not disclosure or fabrication of private model chain-of-thought. Show useful supplied progress summaries and evidence according to provider/runtime support.
